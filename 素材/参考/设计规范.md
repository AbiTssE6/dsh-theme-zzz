# ZZZ 主题设计规范

> 单一事实来源。合并自原 `UI设计分类.md` / `配色规范.md` / `设计规范.md` 三份文档，
> 数值已按当前 `packages/dsh-theme-zzz/client.js` 校对（2026-10-27）。
> 所有数值来自逐像素取样（`示例截图/` 12 张、`按钮与强调色逻辑/` 7 张、`框逻辑/` 3 张），不是估算。

## 0. 一句话

ZZZ 的视觉不是「深色皮肤」，而是三件事：**三层卡片、黄色只做状态、粗字厚边**。

## 1. 卡片（A 类）

由外到内四层，**一张卡片只有这一圈框**：

```
3px      #000000          外描边      box-shadow: 0 0 0 3px #000
9.75px   #444444          灰框        border: 9.75px solid #444
1px      rgba(0,0,0,.6)   暗缝        inset 0 0 0 1px
#282828  + 网点           内侧板      background-clip: padding-box
```

灰框宽度 = 黄环（4px）× 1.618 ≈ 6.5px，后按「1.5 倍」调整到 **9.75px**；外描边与黄环同为 **3px**，
三者是同一套比例，不是三个独立数字。

| 成员 | 选择器 | 圆角 |
|---|---|---|
| 用户消息气泡 | `[class*="_bubble"]` | 16px（显式） |
| 输入框 | `[data-composer-card="true"]`、`[class*="GRgSLq_card"]` | 22px（显式） |
| 新会话键 | `button[class*="wtg9ga_newSession"]` | 14px（显式） |
| 设置对话框 | `[role="dialog"]`、`[class*="AnXs9G_panel"]` | 宿主决定 |
| 菜单 / 下拉 / tooltip | 浮层 `div._portal_`（`position:fixed`，**不可触碰**）→ 可见面板 `div._material_`（**框、网点、斜光都加在这一层**） | 16px（显式） |
| 侧栏工作区 | `[class*="wtg9ga_regionArea"]` | 16px（显式） |
| 右栏工具卡 ×4 | `button[class*="p2k40q_entry"]`（工作区文件 / 浏览器 / Browser Skill / 更多工具） | 宿主决定 |
| 右栏「新建终端」行 | **外层** `div[class*="-34GESq_entry"][data-sidebar-right-guide-entry="terminal"]`；内层 `button[class*="-4GESq_main"]` 是空覆盖层 | 宿主决定 |

**「新建终端」是个特例，单独记一笔：**

- 卡片是**外层 `div`**（`data-sidebar-right-guide-entry="terminal"`），不是里面那个 380 宽的按钮；
- 里面那个 `button[class*="-4GESq_main"]` 是**空元素**（`></button>`），只负责点击/悬停，
  但它自己带 ghost 底色，会在卡片内画出一条灰带 —— 必须整层清成透明（含 `::before`/`::after`）；
- 外层带 `overflow:hidden`，所以**不能给子元素加高度**，否则下方框会被裁掉。
  内容区靠 `padding` 补偿（最终取 `6px 12px`，见 §1.2），不要用 `min-height` 撑高。
- 内边距必须加在**外层容器**上：加在里面那个空按钮上没有任何视觉效果（它的兄弟节点才是内容）。

**这张表就是“所有卡片”的定义。** 以前每次说“给所有卡片加 X”都会漏几处，根因是用
`[class*="_card"]`、`[class*="_entry"]` 这类**语义猜测定选择器**，而宿主的类名并不按这个规律命名。
规则：改“所有卡片”前先按此表逐条核对；出现新卡片组件就补进表里。

### 1.1 宿主原始尺寸（主题关闭时实测）

在 `<html>` 上删掉 `data-dsh-theme-zzz` 属性即可读到宿主原值（所有主题规则都挂在这个属性下）。

| 组件 | padding | height | width | radius |
|---|---|---|---|---|
| `p2k40q_entry` | 0 | 68 | 380 | 0 |
| `-4GESq_main` | 0 / 14 | 66 | 378 | 0 |
| `GRgSLq_card`（输入框） | 8 / 0 | 98 | 950 | 28 |
| `wtg9ga_newSession` | 8 / 12 | 38 | 254 | 12 |
| `wtg9ga_regionArea` | 0 | 706 | 272 | 0 |

**加框时的换算**（`box-sizing: border-box`，框 9.75px、宿主边框 1px）：

```
padding'  = padding − 8.75     （不小于 0）
min-height' = height + 17.5
```

这样内容盒尺寸与宿主一致，框向**外**长，文字不会因加框而挤在一起。

### 1.2 加样式前先确认“谁是卡片”（血泪清单）

给一个组件加框/加内边距之前，**必须先用 DevTools 点中它**，看清被选中节点的角色。
这一节记录的都是真实踩过的坑，每条都导致过返工：

| # | 判断 | 做法 |
|---|---|---|
| 1 | 元素是**容器**（盒子尺寸、背景、边框都在它身上） | 框、背景、内边距全加在它身上 |
| 2 | 元素是**空的子节点**（形如 `></button>`） | 它只是点击/悬停覆盖层，必须整层透明，且要清 `::before`/`::after` |
| 3 | 外层有 `overflow:hidden` | **禁止**用 `min-height` 撑高子元素，下方框会被裁掉；只能改 `padding` |
| 4 | 内容不在该元素的子节点里（兄弟节点承载文字） | 内边距要加在**共同父级**上，加在空按钮上没有任何视觉效果 |
| 5 | 类名含哈希 | 用 `[class*="片段"]`，**片段去掉前导连字符**（`-4GESq_main` → `4GESq_main`），避免一个字符之差整条选择器失效 |
| 6 | 规则写了却“像没生效” | 先用样式表检查确认规则在不在；在 → 是优先级问题，给选择器加 `:not(#zzz-guard)` 抬到 ID 级 |
| 7 | 卡片高度是宿主定死的 | 只能压缩 `padding`，不能改高度 |
| 8 | **两处用同一段声明，一处有效一处无效** | 一定是被别的规则整条覆盖了。读 computed：`backgroundImage` 首层是 `linear-gradient` 且 **5 层** = 完整（斜光+网点）；首层是 `radial-gradient` 且 **4 层** = 斜光被侧栏纸纹盖掉了 |
| 9 | 哈希类名要**精确匹配** | 用 `[class~="rezYhW_menu"]`（按空格分词），**不要**用 `[class*="rezYhW_menu"]`——子元素 `rezYhW_menuBody` 会被子串命中，导致“框套框”双层 |
| 10 | 类名**区分大小写**，且以 DOM 为准 | 真实类是 `VBK9GG_panel`（大写 K），DevTools tooltip 截图里显示成 `VBk9GG_panel`，照抄就整条失效。拿类名用 `el.className`，别照抄截图 |
| 11 | computed 说有背景、像素却是纯色 | 说明**有东西盖住**。按顺序查：`*` 底色 → `::before`/`::after` 材质 → `backdrop-filter` 模糊。三者任一都能把 6px 网点抹成 #282828 |
| 12 | 改完 CSS 先看结构再看效果 | 规则之间混入裸文本（如误留的 `panel own pseudo`）会让**其后所有规则被解析器丢弃**，表现为“改了没反应”。改完必须 `node --check`，并回看插入处上下文 |

「新建终端」同时踩中 2、3、4 三条，是最典型的反例：

```
div.-34GESq_entry[data-sidebar-right-guide-entry="terminal"]   ← 卡片（框、背景、padding 都在这）
 └ button.-4GESq_main  （空元素，只负责点击）                    ← 必须全透明
 └ 图标 / 标题 / 描述 / 快捷键（兄弟节点，承载真正内容）
```

### 1.2.1 「有样式但看不见」的排查顺序

这类问题（网点消失、框被裁、平灰）本质都是**遮挡**，按固定顺序查，别改数值：

1. **量像素**：在空白处取一行，算 stdev。有 6px 网点 → 会看到 ±2~3 的周期波动；恒等于 `40`（`#282828`）→ 被完全盖住；
2. **读 computed**：`backgroundImage` 层数（5 = 斜光+4 网点）、`backgroundSize` 首项是否 `100% 100%`；
3. **查子层**：`el.children` 里谁有非透明 `backgroundColor`；
4. **查伪元素**：`getComputedStyle(el, '::before').backgroundColor`；
5. **查模糊**：`backdropFilter`（`blur(40px)` 足以把网点抹平）。

「智能体团队面板」就是靠这套顺序定位的：computed 5 层齐全 → 像素恒为 40 → 内层 + 自身 `::before` 双重遮挡。

**结论：一个“卡片”的框和内边距，永远加在“真正决定尺寸和背景”的那一层，而不是看起来像卡片的那个元素上。**

### 1.3 已知的“背景覆盖陷阱”

侧栏有一条“纸纹”规则，只画网点、不带斜光，却因为特异性更高而整条顶掉卡片背景：

```css
/* 特异性 (0,3,1)，!important */
[class*="_sidebarCol"] [data-slot="sidebar"] > *,
[class*="_sidebarCol"] [data-slot="sidebar"] > * > * {
  background-image: weave-gap-a ×2, weave-gap-b ×2 !important;  /* 只有网点，4 层 */
  background-size: 6px 6px, 6px 6px, 6px 6px, 6px 6px !important;
}
```

后果：侧栏里的 `新会话键`、`工作区` 两张卡**有网点、没有斜光**，而输入框、气泡一切正常。

修复（写在样式表后段、并抬特异性）：

```css
button[class*="wtg9ga_newSession"]:not(#zzz-guard),
[class*="wtg9ga_regionArea"]:not(#zzz-guard) {
  background-image: var(--zzz-sheen), var(--zzz-weave) !important;
  background-size: 100% 100%, var(--zzz-weave-size) !important;
  background-position: 0 0, var(--zzz-weave-position) !important;
  background-clip: padding-box !important;
}
```

**排查口诀**：样式值一模一样却渲染不同 → 不要改值，去数 `background-image` 的**层数**。

### 1.4 菜单与浮层（两种结构，一条结论）

菜单有两种 DOM 结构，**卡片都画在容器 `[role="menu"]` / `[role="listbox"]` 上**：

| 结构 | 特征 | 子层 |
|---|---|---|
| 浮层型 | `div._portal_`，`position:fixed` + 内联 `left/top` | `_material_` 底板 + `_viewport_` |
| 锚定型 | 容器本身就是 `[role="menu"]._surface_…`，无 `_portal_` | 同上，或（二级菜单）**没有底板** |

**绝对不要碰 `position`**：浮层靠内联 `left/top` 定位，一旦被 `position:relative` 覆盖就掉到文档末尾（已发生过）。

底板 `_material_` 处理成空层，但有两个坑：

1. **它有 `backdrop-filter: blur(40px) saturate(1.5)`**。背景即使透明，这层也会把容器画在背后的
   6px 网点**糊成纯色**——一级菜单“平灰”、二级菜单正常，差别就在这。必须连同
   `-webkit-backdrop-filter` 一起置 `none`。
2. **它铺满整个菜单盒**（`plateBox` 等于菜单尺寸）。若把 9.75px 框画在它上面，框会贴着行；
   画在容器上，菜单会因宽度是内容撑开的而**自然长大 19.5px**，行宽不变。

```css
[role="menu"], [role="listbox"] {
  background: #282828;
  background-image: var(--zzz-sheen), var(--zzz-weave);
  background-size: 100% 100%, 6px 6px, 6px 6px, 6px 6px, 6px 6px;  /* 写死，别用变量展开 */
  background-repeat: no-repeat, repeat, repeat, repeat, repeat;
  border: 9.75px solid #444;
  border-radius: 16px;
  box-sizing: border-box;
  padding: 16px;
  box-shadow: 0 0 0 3px #000, inset 1px 1px 0 rgba(255,255,255,.20), …;
}
[role="menu"] > [class*="_material_"] {
  background: transparent; border: 0; box-shadow: none;
  backdrop-filter: none; -webkit-backdrop-filter: none;   /* 关掉毛玻璃 */
}
```

**二级菜单也要覆盖**：它没有 `_material_`，只有 `[role="menu"]` 容器，所以容器规则才能一并命中。

两条硬约束：

1. **圆角 ≥ 边框 × 2**。6.5px 边框配 10px 圆角会在四角挤出深色楔形；16px 才够。
2. **内层不铺底**。芯片、标签、下拉、字段、输入框一律 `background: transparent`，让卡片的网点
   连续贯通——底色和纹理是同一层信息，两层叠加就变成「框中框」。

**倒角高光**：框的外沿只有**左上**亮、**右下**暗，模拟光从左上打来。实现只用 `box-shadow`，
两个方向的高光抽成变量，**所有卡片共用**（改一处即全站生效）：

```css
--zzz-bevel-hi: inset 1px 1px 0 rgba(255,255,255,.20);   /* 左上受光 */
--zzz-bevel-lo: inset -1px -1px 0 rgba(0,0,0,.28);       /* 右下背光 */

box-shadow:
  0 0 0 3px #000,          /* 外描边 */
  var(--zzz-bevel-hi),     /* 左上受光 */
  var(--zzz-bevel-lo),     /* 右下背光 */
  inset 0 0 0 0.5px rgba(0,0,0,.6),  /* 暗缝 */
  inset 0 0 10px rgba(0,0,0,.35);    /* 内阴影 */
```

**覆盖范围**（7 条链，全部带倒角）：A 类卡片、菜单/下拉、提示气泡、智能体团队面板、
侧栏工作区、右侧栏工具卡、以及 `rezYhW_menu`。新增卡片规则时**必须**带上这两个变量，
否则会出现“别的卡片有立体感、它没有”的孤立感。

自查：卡片内圈左上像素应比底色**亮**（约 +5），右下应比底色**暗**（约 −19）。

**绝不使用 `::after` 叠加层或 `position:relative`**：`box-shadow` 不参与布局，而伪元素叠加需要
定位上下文，曾导致弹出菜单位置塌陷到页面底部。`outline` 也不行——它只能整圈同色。

## 2. 颜色

| 角色 | 值 | 用在哪 |
|---|---|---|
| 品牌黄 | `#fcdd00` | 边框、焦点环、Tab 下划线、品牌位 |
| 黄底渐变 | `#f4ca25 → #e8c01a → #c9a300 → #8c7101` | 选中行（170°，横向几乎无差） |
| 加深黄底 | `#e2bb27` | 选中行的基础色 |
| 绿 | `#00cc0c` | 发送、成功 |
| 红 | `#c81800` | 停止、删除 |
| 蓝 | `#05bbff` | 文件 / 资源图标、链接、thinking 标签（取自参考图实测 5,187,255） |
| 中性灰 | `#b0b0b0` | 绑定 `--dsw-static-neutral-bluish-400`：选中描边、上下文环、说明文字统一为 R=G=B（宿主原值 `#adb2b8` 带蓝调） |
| 橙 | `#f4570e` | 最高级强调、应用图标 |
| 画布底 | `#131313` | 页面 |
| 层 1 / 层 2 | `#1c1c1c` / `#282828` | 侧栏 / 卡片内板 |
| 边框 | `#3a3a3a` / `#444444` | 浅描边 / 灰框 |
| 正文 / 次要 / 说明 | `#f7f7f7` / `#9e9e9e` / `#7d7d7d` | — |
| 反色字 | `#101010` | 黄底上的黑字 |

规则：

- **黄色是状态色，不是底色**。面积占比 < 5%，且永远与黑字配对。
- 黄底只走 `#f4ca25 → #8c7101` 这条色域；`#fcdd00` 是边框用的黄，**两者不混用**。
- 选中态的几何纹理只有 ±3–4/255（≈1.3%），周期约 19px；放大到 28% 就会显脏。
- 高饱和色（绿/红/蓝/橙）**只出现在小面积圆盘或细边框上**，且圆盘本身零立体感。

## 3. 按钮

| 类型 | 外观 | 选择器 |
|---|---|---|
| 设计系统按钮（全部） | `#0b0b0b` 底、8px 圆角、浅色图形、悬停 `#1a1a1a` | `button[class*="1rv3m_"]` |
| 发送 / 停止 | 34px 圆盘，绿 `#00cc0c` / 红 `#c81800`，4px 黑边，扁平 | `[data-composer-card] button[class*="_primary"]` |
| 设置导航单元格 | 未选：透明；选中：黄底黑字（同会话选中行） | `[class*="_navCell"]` |
| 品牌 CTA | 黄底黑字 | 宿主 `_primary`，不覆盖 |

- 图标线宽统一 **1.7px**（`svg, svg *` 全局）。
- 判断形状看宽高比：接近 1:1 → 圆角方块；明显横长 → 腰形（999px）；容器 → 大圆角矩形。

### 3.0 方形按钮一律正圆

任何**近正方形**的图标按钮（16–56px、宽高差 ≤2px）都必须是正圆，方形圆角形状不再使用。

实现是运行时打标而不是 CSS：CSS 无法判断元素是否方正。

```js
// 盒子近方正 -> data-zzz-round；不再是就摘掉
if (square) el.setAttribute('data-zzz-round', '')
else el.removeAttribute('data-zzz-round')
```

```css
[data-zzz-round]{ border-radius:999px; corner-shape:round }
```

- `corner-shape:round` 必须一起写，否则宿主的 superellipse(1.5) 会把圆压扁；
- 插件按钮跳过（`data-dsh-plugin`），形状归插件；
- 打标是双向的，不会把“曾经方正”的按钮永久变成圆。

**为什么不用“抬特异性”硬压**（首版做法，已废弃）：我们的按钮皮肤写
`border-radius:8px !important`，圆形标记要赢只能加 `:not(#zzz-guard)` 抬到 ID 级，
每加一处组件皮肤就要重新算一遍权重。现在改成**令牌间接**：

```css
--zzz-ctl-radius: 8px;                  /* 控件圆角的唯一来源 */
button[class*="1rv3m_"]{ border-radius: var(--zzz-ctl-radius) !important }
[data-zzz-round]{ --zzz-ctl-radius: 999px }   /* 只改变量，不打架 */
```

自定义属性会继承，所以**哪条规则赢都读到 999px**，不需要 `!important` 对撞，也不需要
ID 级 hack。标签条、导航行这些“宽行”仍是字面量 8px（它们永远不是方形）。

> 如果将来宿主提供“图标按钮圆角”之类的专属 token，应优先绑它，连打标都可省去。

### 3.0.1 黄底必须黑字

黄底（`#fcdd00` 及其呼吸渐变）上的文字、图标、描边**一律黑色**，不得使用白字。

实现分两层：

1. **token**：`--dsw-alias-label-primary-inverted` = `#101010`（宿主的“品牌底文字”契约，
   6 处引用）；
2. **运行时兜底**：计算背景色/渐变里出现黄色（alpha>0.35、r≥170、g≥120、b≤120、
   r-g<80、g-b≥60）的元素打 `data-zzz-on-yellow`，其内部强制黑字；变回非黄即摘标。

注意：判据**排除橙色**（`#f4570e` g=87），橙底仍是白字/黑字按原设计（充值按钮为黑字橙底）。

**图标只改颜色，不改画笔。** 黄底上的图标必须靠 `color`（`currentColor`）变黑：
- **禁止**写 `fill:#101010`——`fill="none"` 的描边图标会被涂成实心块；
- **禁止**写 `stroke:#101010`——实心图标会多出一圈描边；
- 写死白色的画笔由运行时改写为 `currentColor`（记录原值，摘标时还原）。

### 3.0.2 选中态只有一个“呼吸盘”配方

所有黄绿呼吸的选中面共用变量 `--zzz-plate`：

```css
--zzz-plate:
  linear-gradient(135deg, rgba(140,113,1,0) 0%, .10 40%, .55 100%),   /* 暗角 */
  repeating-linear-gradient(100deg, rgba(255,255,255,.055) 0 9px, transparent 9px 19px),
  linear-gradient(135deg, var(--zzz-sel-a) 0%, var(--zzz-sel-b) 46%, var(--zzz-sel-c) 100%);
```

| 承载面 | 选择器 |
|---|---|
| 会话行 | `[class*="_sessionRow"][class*="_selected"]` |
| 设置导航格 | `[class*="_navCell"][aria-current]` 等 |
| 页签 | `[role="tab"][aria-selected="true"]`（属性重复一次提权） |
| 筛选胶囊 | `[class*="_pill"][class*="_active"]` 等 |
| dock 徽标 | `[class*="_tabHost_"] [class*="_tabActive_"]` |

改呼吸色只需改 `--zzz-sel-a/b/c`；改纹理/暗角只需改 `--zzz-plate`。

**黄色有两套，不要混用**：

| 用途 | 用什么 | 说明 |
|---|---|---|
| **实心**黄色状态（悬停、按下、选中、文本选区） | `var(--zzz-yellow)` | 纯色，单帧切换（不做颜色过渡） |
| **呼吸盘**（渐变几何高亮） | `var(--zzz-plate)` + `--zzz-sel-a/b/c` | 三层渐变 + 呼吸动画，任何规则都不得用纯色替换它 |

禁止在实心黄状态里写字面色值（`#fcdd00` / `#e2bb27` / `#f4ca25` …）——统一读 token。

> **`--zzz-plate` 必须声明在承载元素上，不能声明在 `html` 上。**
> 自定义属性中的 `var()` 在**声明处**完成替换：写在根元素时，渐变引用的是根元素那一刻的
> `--zzz-sel-a/b/c`（初始值），后代继承到的是冻结值，元素上的呼吸动画就失效（本项目
> 实测过一次，表现为“选中变静态黄”）。正确写法是把配方放在**同一组选中态选择器**里，
> 让每个元素各自解析。

> 页签为什么重复属性选择器：对话标签条有一条 `[data-conversation-tabs] *{background-image:none !important}`
> 的清底规则，重复属性把特异性抬到 (0,4,1) 即可压过它，且**不增加 ID hack**。

### 3.1 滑块开关（两套实现必须同款）

界面上有两个开关组件，样式必须完全一致：

| 实现 | DOM |
|---|---|
| 宿主设计系统 | `button[role="switch"][aria-checked] > span`（thumb） |
| 插件 think-bounce-pet | `span.dsh-tbp-switch > input[type=checkbox] + i`（`i::after` 是 thumb） |

统一规格（**与长滑条同一套语言**，2026-10-29 改版）：

```css
轨道  36 × 20, radius 999
      关 = --zzz-slider-groove（深槽）+ 1.5px --zzz-slider-keyline 黑边
      开 = --zzz-slider（蓝渐变，与滑条同一渐变）

```

- 旧版“开=黄底 + 黑拇指”已废弃，理由是滑条是全站唯一使用渐变蓝的控件，开关跟随它；
- 两套都**不要**内阴影；开态的光晕只画在拇指上，不画在轨道上（否则空槽也会发光）；

- 插件版只改轨道/拇指颜色（`i` 与 `input:checked + i::after`），几何保持原样。

### 3.1.1 长滑条：全部走 token

```css
--zzz-blue          /* 主蓝 #05bbff */
--zzz-slider-to     /* 渐变终点 */
```

### 3.2 卡片悬停：只亮内部，不亮框

**统一规则**：卡片 hover 时**面板底色提亮一档，灰框保持不变**。

```css
button[class*="_entry"]:hover:not(#zzz-guard),
button[data-sidebar-right-guide-entry]:hover:not(#zzz-guard),
:has(> button[class*="4GESq_main"]):hover:not(#zzz-guard) {
  border-color: var(--zzz-frame-color);  /* 钉住灰框 */
  background-color: #333333;             /* 只动底色，网点斜光保留 */
}
```

三个坑：

1. **宿主会自己提亮灰框**。实测框架色 `#444444`（68）→ `#4F4F4F`（79），而面板 `40` 不动。所以必须显式钉住 `border-color`，否则变成“框也亮、内也亮”的双重高亮。
2. **宿主那条 hover 规则的优先级高于类级**。`(0,3,1)` 压不住，要抬到 `(1,3,1)`——即加 `:not(#zzz-guard)`。表现是“改了没反应”，很容易误判为选择器写错。
3. **终端行是包裹层不是按钮**。它的内层按钮被强制成“普通态与 hover 态都透明”，所以宿主 hover 完全失效；必须用 `:has()` 命中外层包裹元素才有反馈。

判断依据同样是量像素：hover 前后**只有灰框那 12 物理像素变化**＝宿主在改 `border-color`；**只有面板变化**＝我们要的效果。

## 7. 深浅模式

ZZZ 没有亮色版本，**两套模式必须完全一致**。官方提供了专门的机制，比“强制切深色 + 轮询”干净得多。

### 7.1 官方机制（源码依据）

`dsh-client-ui-theme` 运行时：

```js
overrideTokens(source, tokens)   // tokens: 每个 token → { light, dark }
buildSnapshot() {
  const resolvedId = preference === "system" ? (media.matches ? "dark" : "light") : preference;
  const active = this.themes.find(t => t.id === resolvedId);
  tokens[name] = modes[active.colorScheme];   // 按当前方案取每 token 的对应值
}
```

两条结论：

1. **`register({ tokens })` 与 `overrideTokens` 都要求 `{ light, dark }` 形式**。传裸字符串时
   `modes[active.colorScheme]` 取到 `undefined`，**注册的 token 等于没生效**——主题早期一直靠
   CSS 的 `!important` 块在撑，原因就在这里。
2. `overrideTokens` 是「token 级叠加覆盖层」的官方 API（文档原文：token 级类比 slot shading）。
   把**两种模式填成同一个值**，深浅模式就在**源头一致**，既不用强制偏好，也不用轮询。

### 7.2 本主题的做法

```js
const dualTokens = palette => Object.fromEntries(
  Object.entries(palette).map(([k, v]) => [k, { light: v, dark: v }])
)
theme.overrideTokens('dsh-theme-zzz:palette', dualTokens(DARK))
theme.register({ id: 'zzz', colorScheme: 'dark', tokens: dualTokens(DARK) })
```

### 7.3 绑定范围：只绑“会变”的 token（106 / 403）

不需要把 403 个 token 全绑一遍。实测两个调色板：

| 类别 | 数量 |
|---|---|
| 深浅两套取值**不同**的 token | **106**（alias 89 / specific 11 / static 1 / font 1） |
| 两套取值相同的 token | 297（无需绑定） |

把这 106 个全部绑成深色值，浅色/深色渲染就**在 token 层完全一致**。绑定清单由脚本从
`dsh-client-ui-theme` 产物里生成（`.scratch/bind_all_scheme_tokens.py`），共 117 个 token
（含主题自定的 ZZZ 颜色）。

**两条必须遵守的规则**：

1. **后写覆盖先写**：生成块若重复主题已定制的 token，会把 ZZZ 颜色改回宿主色。
   生成前先过滤已存在的键（本次生成器已含该过滤），否则 `--dsw-alias-brand-primary`
   会从 `#fcdd00` 变回宿主的蓝色；
2. **不要用半透明色绑边框**：`border-l1..l4` 原来只在深色绑了实色，`l3/l4` 仍是宿主值
   （深色半透明白 / 浅色半透明黑），深浅切换时线条黑↔白跳变。统一成实色灰
   （`#3a3a3a / #444444 / #4a4a4a / #525252`）后两者同貌。

三层保障，按优先级：

1. **官方覆盖层**：`overrideTokens` 两种模式同值 → 用户选 light / dark / system 渲染都一致；
2. **CSS 强制**：DARK 全表以 `!important` 写在 `html[data-dsh-theme-zzz]` 上（主题服务不可用时仍成立）；
3. **兜底**：`color-scheme: dark`、`body` 底色、placeholder/selection/caret 颜色。

**已移除**：`theme.setTheme('dark')` 的 700ms 轮询。它篡改用户偏好（设置页选浅色会被反复改回），
而官方机制已能让两种模式同貌，没必要强改偏好。旧运行时没有 `overrideTokens` 时，退化为一次性重定向（不轮询）。

## 9. 与官方规范的偏差（必须有意识地保留）

官方权威文档见 [`DSH文档/web-styling.zh.md`](DSH文档/web-styling.zh.md)（Web UI 样式参考）。
它规定的是 DSH 自己的设计系统；**ZZZ 主题是在这套系统上做的“换皮”**，因此存在有意为之的偏差。
下表把偏差写清楚，避免以后误以为是 bug 去“修正”。

| 官方规则 | 官方做法 | 本主题的做法 | 原因 |
|---|---|---|---|
| 高层级表面（菜单、浮层、对话框、面板、按钮、输入框） | `border: 0` + `box-shadow: var(--dsw-elevation-panel/prominent/soft)`，0.5px 发丝线是第一层投影 | **9.75px `border` + 3px 黑环** | ZZZ 的卡片语言就是“厚灰框 + 黑描边”，这是风格核心，不能退成发丝线 |
| 中性边框/分割线 | 一律 `0.5px`，更宽会被 `ui-theme` 的 elevation spec 拒绝 | 暗缝已改 **0.5px**（合规）；外描边 3px、灰框 9.75px 属风格，保留 | 外框是风格核心；暗缝是纯中性细线，没有理由不遵守 |
| 不得把 `--dsw-alias-border-*` 与 elevation 投影配对 | 用 elevation token 表达层级 | 我们从不使用 `--dsw-alias-border-*`，也不使用 elevation 投影 | **符合，非偏差** |
| 菜单材质由 `--dsw-menu-surface-fill` + `--dsw-menu-backdrop-filter` 组成，**功能与平台 CSS 不得覆盖** | 改 token | **已改为 token 驱动**：主题里设 `--dsw-menu-surface-fill: #282828`、`--dsw-menu-backdrop-filter: none`；CSS 只补“网点 + 斜光”纹理（token 无法表达纹理） | 底色与模糊走官方 token；仅纹理必须用 CSS |
| 正圆/胶囊必须配对 `corner-shape: round` | 两个声明成对出现 | **已补齐**：按钮、图标键、chip/pill/tag/badge、导航格、会话行、品牌图标统一声明 `corner-shape: round` | — （已消除） |
| 功能包 CSS 不得含主题选择器 | 主题由主题包负责 | 主题包内统一用 `html[data-dsh-theme-zzz]` 前缀 | **符合，非偏差**（我们就是主题包） |

**结论**：这些偏差是“风格 vs 设计系统”的取舍，不是遗漏。动它们之前先确认视觉目标没变。

## 10. 实现约束（踩过的坑）

| 约束 | 原因 |
|---|---|
| 选择器优先用 `data-*` / `aria-*` | CSS Modules 哈希随构建变；`data-conversation-tabs`、`data-sidebar-right-guide-entry` 这类语义属性不会 |
| 只加 `box-shadow`/`outline`，不铺背景 | 铺背景会盖掉编辑器面板、纹理和子元素 |
| 注意 `outline` 是第三条绘制通道 | 背景/边框/阴影都清空后，`outline` 仍在，曾伪装成「黑线」 |
| 改 `client.js` 前先备份 | 文件无 git；索引切片曾删掉整段 CSS |
| 改完必须重装插件再看 | 客户端 bundle 会缓存，刷新页面不一定加载新代码 |
| 改色优先改 token | 见 §11 |

## 11. Token 优先（最高优先级，不是“后续方向”）

[`DSH-Token-清单.md`](DSH-Token-清单.md) 列了宿主全部 **403 个 `--dsw-*` token**（深/浅色原值 + 本主题覆盖情况）。

**规则：任何外观问题，先查官方有没有对应 token；能用 token 直接解决就用 token，
不要写选择器。** 理由不是风格偏好，而是正确性：

- token 是**组件的构造层**——一个值决定所有使用该组件的实例，宿主五页、插件十页一起生效；
- 选择器是**事后覆盖**——要靠类名/结构猜中每一个实例，漏一个就出现“两张卡一深一浅”；
- 官方文档明确要求“功能组件使用 `--dsw-alias-*` 语义 token，不得复制静态色板值”。

优先级阶梯（已固化为 §13.5）：

```
① 组件 token（--dsw-alias-* / --dsw-specific-* / --dsw-menu-* / --dsw-elevation-*）
② 语义锚点（data-slot / data-dsh-plugin / data-* / role / aria-*）
③ 类名（宿主组件后缀，必须套在语义容器内）
```

③ 只用于 token **表达不了**的东西：模糊（`backdrop-filter` 没有 token）、网点/斜光纹理、
伪元素装饰、几何形状校正。

### 11.1 实战判例：设置页卡片（2026-10-29）

问题：十页设置界面的卡片深浅不一。

错误路径：用 JS 按“圆角 ≥ 6px / 内边距 ≥ 8px / 层级下钻”猜卡片 → 身份卡圆角来自子元素、
被跳过；后来换 token 后又被一条老规则 `[role="dialog"] [class*="_card"]{background:transparent
!important}` 清掉，而 `_balanceCard` 不含 `_card` 子串所以保留 → 一深一浅。

正确路径（一次解决）：

```js
'--dsw-alias-settings-card-fill':   'rgba(16,16,16,.34)',
'--dsw-alias-settings-card-stroke': 'transparent',
```

外加把那条旧清扫规则限定为 `[role="dialog"]:not([data-shortcut-modal])`，即**设置弹窗
交给 token，旧规则不再插手**。

教训：

1. 先 `grep` token 清单（`settings-card` → 命中 `-fill` / `-stroke`），十有八九已经有现成的；
2. 改 token 后**必须回头检查有没有老规则在覆盖同一属性**——`grep` 组件类名/属性，
   看有没有 `background:transparent !important` 这类清扫；
3. 模糊这类 token 覆盖不到的效果，判据也应“跟着 token 走”（computed 背景色 = token 值），
   而不是另立一套几何启发式。

### 11.1.1 绑 token 之前先数它有多少消费者

token 是**共享**的。改之前必须问一句：这个 token 还有谁在用？用错了会把一堆无关组件一起改坏。

判例（Agent 预设卡片，2026-10-29）：想让“选中卡片”不要填充色，看起来只要把
`--dsw-alias-bg-module-platform` 改成 `transparent` 就行。实际 `grep` 一遍发现有 **20 多个消费者**：

```
dsh-client-locale            .selector
dsh-client-ui-theme          body / .selected / .stepper
dsh-client-ui-shortcuts      .keyBadge / .recorder / .button
dsh-client-ui-settings-models .editor / .addCard / .setupCard
dsh-client-ui-trajectory     .turnLabel
…
```

改一个值会把快捷键键盘底、模型编辑器、轨迹标签全变成透明。**结论：这个 token 不能动。**

正确的分工是：

| 属性 | 由谁决定 |
|---|---|
| 选中卡片填充 | token `--dsw-alias-bg-module-platform`（本主题已绑为中性 `#333333`）✅ |
| 卡片文字颜色 | **不覆盖**，用宿主自己的白色 ✅ |
| 断掉那条冷灰描边（`static-neutral-bluish-400`，全站共享的原色） | 选择器，只此一处 |
| 黄绿呼吸描边（`animation` + `border-color`） | 选择器 + 伪元素（token 无法表达动画） |

**判据**：只有“组件专属 token”（名字里带组件名，如 `-settings-card-`）才适合改；
名字里是通用语义（`bg-module-platform`、`border-l4`、`elevation-*`）的都是共享项，
改动前先 `grep` 消费者数量，改一处等于改全站。

### 11.2 为什么“厚框”没有改成 token

`--dsw-elevation-stroke` 的语义是：

```css
--dsw-elevation-panel: var(--dsw-elevation-stroke), 0 3px 8px #00000008, 0 0 16px #00000005;
--dsw-elevation-stroke: 0 0 0 .5px var(--dsw-elevation-stroke-color);
```

它是 **`box-shadow`**，也就是画在盒子**外部**。而我们的 9.75px 灰框是 `border`，
`box-sizing: border-box` 下画在盒子**内部**。

两者不等价：

- 画在外面 → 卡片视觉尺寸超出布局占位，输入框、右栏卡在窄列里会互相遮挡；
- 画在里面 → 内容盒缩小，但外轮廓和布局一致，这也是当初排版能对齐的前提。

所以厚框保留 `border`，但已收敛成两个变量，改一处即可全站生效：

```css
--zzz-frame-w: 9.75px;
--zzz-frame-color: #444444;
border: var(--zzz-frame-w) solid var(--zzz-frame-color);
```

### 11.3 胶囊与正圆：已按官方规则配对

宿主在 `@supports (corner-shape: superellipse(1.5))` 里对**所有元素**应用超椭圆，
会把 `border-radius: 50%` 的圆和 `999px` 的胶囊压成“方一点的圆”。
官方规范要求这类正圆必须配对 `corner-shape: round`，已统一处理：

```css
button, [role="button"], _iconButton, _chip, _pill, _tag, _badge,
_navCell, _sessionRow, a.linkButton, img.zzz-brand { corner-shape: round; }
```

**结论：全应用只有一套「鼠标移上弹出、移走消失」的浮窗实现**，来自官方前端共享运行时，
不是各包各写一份。证据在 `D:\DSH\resources\app.asar` 的
`@deepseek-ai/dsh-web-frontend/dist/assets/index-BXV-oxvX.js`：

```js
className: y8.bubble,          // = _bubble_44yfq_1
"data-side": r, "data-portal": h || void 0,
"data-pinned": w || void 0, "data-align": i,
"data-has-shortcut": t?.length ? !0 : void 0,
```

### 12.1 DOM 契约

| 部分 | 选择器 | 说明 |
|---|---|---|
| 气泡本体 | `[role="tooltip"]`（类名 `_bubble_44yfq_1`，哈希会变） | 用 **role 选择器**，不绑哈希 |
| 变体 | `data-side` / `data-portal` / `data-pinned` / `data-align` / `data-has-shortcut` | 只影响定位，**不影响配色与边框**，无需分别书写 |
| 文本 | `[class*="_label"]` | 单一文本节点 |
| 快捷键键帽 | `[class*="_key"]` / `[class*="_keys"]` | 读取官方 token `--dsw-alias-tooltip-key-bg` |

### 12.2 覆盖情况

| 项目 | 状态 |
|---|---|
| 灰框 9.75 / 圆角 16 / 网点 + 斜光 / 倒角 / 黑环 | ✅ `[role="tooltip"]` 卡片规则 |
| 内层不铺底（否则盖住纹理） | ✅ `[role="tooltip"] > *` 透明化 |
| 文本颜色与行高 | ✅ `[class*="_label"]` |
| 快捷键键帽 | ✅ 重绑 `--dsw-alias-tooltip-key-bg: #3a3a3a`，不写死颜色 |
| 内边距 | ✅ 6px（从 12px 收到 6px，因为首个子元素自带 12px 已清） |
| 毛玻璃 `backdrop-filter: blur(40px)` | ✅ 置 none（否则网点被糊平） |

### 12.3 覆盖不到的浮窗

- **原生 `title` 提示**：由操作系统绘制，不在 DOM 内，任何 CSS 都无法改变；
- **点击型浮层**（菜单、下拉）不是本类，见 §1.4。

判断方法：悬停后截图，若截不到浮窗而人眼能看到，基本就是原生 `title`。

### 12.4 毛玻璃浮窗的做法（两个组件、一套配方）

浮窗共 **两个独立组件**，视觉必须一致：

| 组件 | DOM 契约 | 命中方式 |
|---|---|---|
| 通用 tooltip | `span._bubble_44yfq_1[role="tooltip"]` | `[role="tooltip"]`（语义属性，哈希变了也不失效） |
| 会话悬浮预览卡 | `div._card_38jqx_9._copyable_38jqx_21[role="button"]`，`position:fixed` 244×96 | `[class~="_card_38jqx_9"][role="button"]`（精确 token，避免误伤同模块的代码块卡） |

另有三个组件使用同一套玻璃语言（配方完全相同）：

| 组件 | 命中方式 |
|---|---|
| 文件改动卡片 | `[class*="HOHHba_card"]`（玻璃只在卡片这一层，header/list/row 全透明） |
| 文件改动行 | `[class*="HOHHba_row"]`，行间用 `inset 0 0.5px 0 rgba(255,255,255,.07)` 分节奏 |
| 底部输入条 | `[class*="GRgSLq_root"]`，圆角 20px |

**配方**（所有玻璃面逐项相同）——**无任何立体感**：无边框、无亮边、无投影、无内高光。
颜色与模糊收在 4 个变量里，**改一处全站同步**（2026-10-29 统一）：

```css
background-color: var(--zzz-glass-fill);        /* rgba(16,16,16,.34) */
border: 0;                                     /* 无边框 */
border-radius: var(--zzz-glass-radius);        /* 12 / 16 / 20 三档，见下 */
box-shadow: none;                              /* 立体感一律不给 */
backdrop-filter: var(--zzz-glass-blur);        /* blur(14px) saturate(180%) */
-webkit-backdrop-filter: var(--zzz-glass-blur);
background-image: none;                        /* 去掉网点/斜光，纹理交给模糊 */
```

变量定义（`client.js` 的 token 块）：

| 变量 | 值 | 用在 |
|---|---|---|
| `--zzz-glass-fill` | `rgba(16,16,16,.34)` | 所有玻璃面；同时是 `--dsw-alias-settings-card-fill` 的值 |
| `--zzz-glass-fill-strong` | `rgba(16,16,16,.45)` | **仅**底部输入条（上下留白带宽，需要更实一点） |
| `--zzz-glass-blur` | `blur(14px) saturate(180%)` | 所有玻璃面 |
| `--zzz-glass-radius-sm` | `12px` | tooltip、智能体团队 / 子智能体浮窗 |
| `--zzz-glass-radius` | `16px` | 设置卡片、文件改动卡、Agent 预设卡 |
| `--zzz-glass-radius-lg` | `20px` | 底部输入条 |

判定“是不是同一套玻璃”的方法：`grep 'backdrop-filter'`，未走变量的都是漏网的。

**对话框玻璃（2026-11-03 修复）**：宿主的面板/浮窗直接读 `--dsw-menu-backdrop-filter` 作为
`backdrop-filter`，而卡片规则又把 `[role="dialog"]` 填成不透明 `#282828`，两者叠加就会“玻璃丢失”。
现在的配方：

- `--dsw-menu-backdrop-filter` 绑到 `var(--zzz-glass-blur)`（不再置 none）；
- `[role="dialog"]:not([data-shortcut-modal])`、`[role="alertdialog"]` 用
  `--zzz-glass-fill-strong` + `--zzz-glass-blur`，保留 ZZZ 边框/斜角；
- 菜单 / 列表 / 提示仍由 material 规则强制 `backdrop-filter:none`，保持扁平。

**四条踩过的规律**：

1. **填充过实就没有玻璃感**。第一版 `.72` 配上 `blur(18px)`，在深色页面上看起来就是一块实灰——
   模糊一片纯色仍是纯色。填充要压到 `.18`~`.30` 区间才透得出来。
2. **模糊量与填充量要反向调**。填充降低时若同时加大模糊，会得到“透着但很糊”的脏感；
   正确方向是**降低填充 + 降低模糊**（本次 `.30/26px` → `.18/14px`），背后内容变成
   “轻微失焦、仍可辨认形态”。
3. **不要靠加亮边缘解决可读性**。用户明确要求不加亮线；若文字与背景打架，
   只调文字（`text-shadow` / 字重），或给文字区加局部窄底，**不动整体透明度与边缘**。
4. **玻璃不允许有任何立体感**。投影（`0 10px 30px`）、内亮边（`inset 0 0 0 .5px`）、
   顶部受光（`inset 0 1px 0`）**全部删除**，`box-shadow` 直接 `none`。
   玻璃的边界只由填充与模糊产生，靠模糊边缘自然形成，不靠画线托起。

**嵌套禁区**：玻璃只能画在**一层**上。文件改动卡片第一版把玻璃同时画在 header 和每个 row 上，
结果每层都有自己的圆角与底色，半透明层层叠加 → 越叠越暗、像一堆错位的卡片。
正确做法：外层容器承载玻璃，内层（header / list / row / 各种 span）一律 `transparent`。

**可读性权衡**：`.18` 已接近下限，背景明暗会明显改变浮窗亮度。再往下必须靠文字侧手段补偿。

**验收方式**：记录器抓计算样式，确认 `bg` 与 `bf` 同时生效：

```js
{ cls:"_bubble_44yfq_1", role:"tooltip",
  bg:"rgba(24,24,27,0.18)", bf:"blur(14px) saturate(180%)" }
```

只看到 `bg` 变了、`bf` 是 `none`，说明 `backdrop-filter` 被上游（例如带 `filter`/`transform`
的容器创建了新的包含块）吃掉，需继续向上查。

### 12.5 破图占位（缩略图“白框”）——CSS 只能做一半，必须配 JS

插件市场里加载失败的缩略图 `img.nUhMVa_cardShot` 会露出一圈**白框**（还会在右/上侧留下
更细的残线，且只出现在部分卡片上）。排查过程与结论：

| 排查项 | 结果 |
|---|---|
| `img` 的 `border / outline / box-shadow` | 全为 `0 / none` |
| `img` 的 `::before / ::after` | 透明、`content: none` |
| 祖先链底色（img → cardShots → introScope → card） | 全部 `rgb(43,43,43)`，无白色 |
| 缩略图区域滚动条 | 曾是一条 `#9F9F9F`／7px 的亮条，**已单独修掉**（`color-scheme` 被解析成浅色） |

**真正来源**：浏览器对加载失败图片**自己绘制的占位装饰**。它有两个特点：

1. 用元素的文字颜色绘制 → `color: transparent` 能压掉一部分；
2. **会画到元素盒子之外**（亚像素定位时偏出 1px）→ `clip-path: inset(1px)` 只能裁盒子内部，
   所以残留线条总在右/上侧、且只在部分卡片上出现。

**结论：纯 CSS 无法根除**。最终方案是主题侧 JS 打标记 + CSS 隐藏：

```js
// 捕获阶段监听，任何失败的缩略图立即打标记
window.addEventListener('error', (e) => {
  const n = e.target
  if (!n || n.tagName !== 'IMG') return
  if (String(n.className || '').indexOf('nUhMVa_cardShot') < 0) return
  if (n.complete && n.naturalWidth === 0) n.setAttribute('data-zzz-broken', '')
}, true)
// 首帧前就已失败 / React 重建的节点：启动扫一次，再每 500ms 扫一次共 60s
```

```css
img[data-zzz-broken]{ visibility:hidden !important; }
```

**要点**：

- 判定条件必须是 `complete && naturalWidth === 0`（只看 `naturalWidth` 会把**仍在加载**的图误杀）；
- **不要**用 `clip-path` 裁缩略图，它会把加载成功的截图也裁掉 1px 边缘，且治不了盒外残留；
- 扫描要**自动停止**（60 秒后 `clearInterval`），不要留常驻定时器；
- 这类“浏览器自己画的东西”是 CSS 的能力边界，判断时先看 **computed 是否真的没有边框/伪元素**，
  确认后再考虑 JS。

## 13. 第三方插件的外观边界（通用做法）

反复出现的误伤（`_button` 后缀被插件复用、`aria-label` 含“记忆”命中侧栏行、图标被统一加粗）
根因是同一个：**主题用宽泛选择器去“猜”宿主组件**。官方规则写得很清楚：

> 功能组件使用 `--dsw-alias-*` 语义 token，不得复制静态色板值或写入颜色字面量；
> 全局样式表归 `ui-theme` 所有，组件样式以 CSS Modules 放在组件旁。

即：**插件的 DOM 归插件自己**，主题只应通过 token 影响它。所以要按优先级选锚点：

| 优先级 | 锚点 | 说明 |
|---|---|---|
| 1 | **token 层**（`--dsw-*`） | 改动一处，所有插件自动跟随；不碰它们的 DOM |
| 2 | **语义标记** `data-dsh-plugin` / `data-dsh-part` / `data-slot` / `role` / `aria-*` | 官方约定的稳定契约（与 `data-dsh-automatic-focus` 同族） |
| 3 | 宿主组件类名（`1rv3m_`、`4GESq_`） | 只对宿主自有组件生效，且必须排除插件子树 |
| 4 | 精确类名 `[class~="ypSjoa_button"]` | 最后手段，必须注释说明为何不能用前三类 |

### 13.1 全局规则必须排除插件子树

```css
/* 宿主图标统一线宽，但插件图标保留它自己画的粗细 */
svg:not([data-dsh-plugin]):not([data-dsh-plugin] *) { stroke-width: 1.7 }

/* 宿主按钮皮肤，跳过：插件自身 / 插件内部节点 / 内容就是插件视觉的宿主按钮 */
button[class*="_button"]:not([data-dsh-plugin]):not([data-dsh-plugin] *)
                       :not(:has([data-dsh-plugin]))
```

`:has([data-dsh-plugin])` 是关键补充：**“存入记忆”按钮本身没有插件标记，只有里面的 `<svg>` 有**，
只做子树判断挡不住它。

### 13.2 判定流程（遇到新插件时）

1. 先看它是否只消费 token —— 是的话**什么都不要写**，token 已经覆盖；
2. 需要单独调整时，在 DOM 里找 `data-dsh-plugin` / `data-slot`，用这些属性写规则；
3. **不要**用 `[aria-label*=…]` 这类“按文案猜”的选择器：文案会跨组件重复（“存入记忆” / “记忆系统”）；
4. **不要**用 `button[class*="_button"]` 这种后缀匹配给插件兜底：`_button`、`_card`、`_row` 这类后缀
   插件用得比宿主还多；
5. 类名以 **`el.className` 或 Elements 复制的 HTML** 为准，DevTools 悬停提示会显示错大小写
   （`ypSjoa_button` vs `ypSJoa_button`、`VBK9GG_panel` vs `VBk9GG_panel`）。

### 13.3 后缀匹配可以，但必须套在语义容器里

同一个设置弹窗里，各页面各有一组模块哈希，可它们都以同一种后缀结尾
（`LcmJYa_card` / `LcmJYa_balanceCard`）。这时**后缀匹配是安全的**，前提是外面先套一个
稳定的语义容器：

```css
/* 语义容器限定作用域，内部再用后缀匹配 */
[data-shortcut-modal="settings"] [class$="_card"],
[data-shortcut-modal="settings"] [class$="_balanceCard"] { …玻璃… }
```

三条规则：

1. 用 `[class$="_card"]`（**后缀**）而不是 `[class*="_card"]`（**子串**）——后者会把
   `_cardTitle`、`_cardAction` 一起命中，造成玻璃套玻璃；
2. 玻璃只画在卡片这一层，卡内元素统一清空底色，但要**排除**强调按钮（`linkButton`）与
   分隔线（`_divider`），否则充值按钮的橙色底会被清掉；
3. 作用域容器优先选 `data-*` 语义属性，其次才是 `[role="dialog"]` 这类结构属性。

### 13.5 设置页卡片：先找组件 token，再谈选择器

官方设计系统给设置卡片留了**专用 token**（在 `DSH-Token-清单.md` 里能查到）：

```
--dsw-alias-settings-card-fill    卡片填充
--dsw-alias-settings-card-stroke  卡片描边
```

绑定它们等价于“改这个组件的外观”，**所有页面的卡片自动统一**——宿主五页、插件五页
都一样，不需要认类名、不会有嵌套、不会漏掉某张卡：

```js
'--dsw-alias-settings-card-fill': 'rgba(16,16,16,.34)',
'--dsw-alias-settings-card-stroke': 'transparent',
```

**毛玻璃的模糊无法通过 token 传递**（没有对应 token），所以模糊仍由运行时打标补上；
但打标的判据改成“**computed 背景色等于该 token 解析出的颜色**”，即跟着 token 走，
不再依赖圆角/内边距之类的几何猜测：

```js
if (getComputedStyle(el).backgroundColor !== 'rgba(16, 16, 16, 0.34)') continue
el.setAttribute('data-zzz-glass', '')
```

即使某张卡漏标，它的**填充色也已经是统一的**，只是少了模糊——不会再出现“两种深浅”。

**结论**：组件的 token 优先级高于选择器；选择器只用来补 token 表达不了的东西
（模糊、网点、伪元素）。

### 13.4 🔒 锁定项：充值按钮必须是橙底黑字

`a[class*="linkButton"][class*="primary"]`（账号页的「充值」）**固定为橙色底 + 黑字**：

```css
background: var(--zzz-orange);   /* #f4570e */
color: #101010;
border: 0;  box-shadow: none;
:hover → #ff6a22
```

- 它是全站**唯一**把强调橙当作填充色的地方；
- 任何“清空卡内底色 / 统一按钮风格 / 降低饱和度”的批量规则，**必须排除 `linkButton`**，
  否则这个按钮会变成透明或灰色；
- 已经写过两次同样的坑（第一次是普通按钮规则、第二次是设置页玻璃清底），改样式时先搜
  `linkButton` 看有没有被清掉。

### 13.6 新组件的固定动作（Checklist）

给任何**新组件**（宿主升级带来的、或新装的插件）做样式时，按这四步走，不要跳步：

**① 先问 token**

```
grep <组件名关键词> 素材/参考/DSH-Token-清单.md
```

命中专属 token（名字里带组件名，如 `--dsw-alias-settings-card-*`）→ 直接绑，结束。
只命中通用语义 token（`bg-module-platform` / `border-l4` / `elevation-*`）→ **先数消费者**，
消费者 >3 个就不要为单个组件改它。

**② 找语义锚点**

按优先级找：`data-slot="…"` → `data-dsh-plugin` / `data-dsh-part` → `role` / `aria-*`
→ 组件自己的 `data-*`（如 `data-dockkit-strip-tabs`、`data-team-panel`、`data-active`）。
这些是宿主/插件给的外部契约，比类名稳定。

**③ 才用类名**

- 用**组件专属前缀**（`nUhMVa_`、`VoX2oq_`），不要用 `_button` / `_card` / `_row` 这类通用后缀；
- 后缀匹配（`$=`）优先于子串（`*=`）；
- 类名以 `el.className` 或 Elements 复制的 HTML 为准 —— DevTools 悬停提示会显示错大小写。

**④ 落地前做三个检查**

1. `grep` 一遍新选择器的关键词，看有没有**旧规则**在覆盖同一属性（这正是“两张卡一深一浅”
   与“开关一直是黄色”的根因）；
2. 写清“为什么”的注释，并留一句**回滚提示**（改哪个值能退回去）；
3. `node --check`，刷新页面肉眼确认；结构性改动追加一条到 `packages/dsh-theme-zzz/CHANGES.md`。

## 14. 🔒 不要碰滚动（2026-10-29 实测）

会话输出的滚动跟随属于宿主 JS（`dsh-client-ui-chat` 的 `toBottom`），**主题不要试图改**。
两条实测踩过的坑：

| 改动 | 后果 | 原因 |
|---|---|---|
| `[data-conversation-scroll]{ scroll-behavior:smooth }` | **流式跟随直接丢失** | 宿主靠“滚动位置是否贴底”判断是否跟随；平滑滚动是逐帧动画，每个 scroll 事件时都不在底部 → 判定为用户已手动滚动 → 关闭跟随 |
| `[data-conversation-scroll]{ scroll-padding-bottom:calc(var(--dsh-composer-height) + 24px) }` | **打字时页面自己滚动** | 该属性改变滚动末端计算；打字让输入框长高 → 宿主 ResizeObserver 重写 `--dsh-composer-height` → “底部”位置跟着变 → 容器被推着走 |

宿主的实现事实（改任何滚动相关样式前先看）：

- 跟随尾部时 `behavior:"instant"`，用户点回到底部时 `behavior:"smooth"` —— 所以 CSS
  `scroll-behavior` 只能影响**未指定行为**的程序化滚动，管不到流式跟随；
- 输入区高度由 `ResizeObserver` 写入 `--dsh-composer-height`，`.toBottomSlot` 用
  `bottom: calc(var(--dsh-composer-height,152px) + 16px)` 定位；
- `ui-layout` README 明确：“挤压重排期间无滚动锚定——布局变化可能移动读者的视口”。

**允许做的**：字体预加载（避免流式输出中途字体 swap 导致整屏重排）——这条已保留。
**不要做**：`scroll-behavior`、`scroll-padding`、`overflow-anchor`、接管 `scrollTo`。

流式输出偶尔“向上跳一段”是宿主行为（内容增长与高度变量之间存在一帧差），
跳动幅度正比于输入区高度；想减小只能压缩玻璃条的垂直内边距，而不是改滚动。

## 16. 背景动效：官方依据与约束（2026-10-29 核对）

结论：**官方没有“主界面背景动效”的现成方案**——没有背景插槽、没有动效 token、没有背景图/壁纸 token；
动效只能由主题自己在 CSS 里做。官方给的是**可复用的运动参数**、**归属规则**和一组**必须先避开的约束**。
依据来自 `DSH文档/` 下 9 份包内 README（与安装版 0.2.1-rc.4 的包内 README 逐字节一致；`conversation`
仅差一行）和安装包内的样式实现（ui-theme `base.css`、ui-layout、web-frontend 打包 CSS）。
本节只记录依据；具体实现方案见 §17。

### 16.1 官方有、可直接用

### 16.2 会直接卡方案的官方事实（动手前先读）

1. **不要画在 `body`**：`body { background: var(--dsw-alias-bg-base) }`，但 AppFrame 自己铺 bg-base，且
   `position: relative; overflow: hidden`；macOS 桌面还会把 body 设成 `transparent`（Electron 原生材质）。
   可见的“主界面背景”是 AppFrame / 中心列，不是 body。
2. **玻璃面逐帧重采样背景**：菜单/浮层模糊画在独立图层上、采样页面内容（[`web-styling:29`](DSH文档/web-styling.zh.md#L29)）；
   本主题玻璃是 `blur(14px) saturate(180%)`（菜单已 `--dsw-menu-backdrop-filter:none`）。背景一动，
   玻璃区每帧重算模糊 → 最大的性能/画质风险（§1.3 已实测 blur 会把网点糊平）。
3. **theme-color 只测一次**：layout 呈现器把“渲染出的背景”测量为唯一颜色依据写进 `<meta name="theme-color">`
   （[`layout README:47`](DSH文档/dsh-client-ui-layout__README.zh.md#L47)、[`:59`](DSH文档/dsh-client-ui-layout__README.zh.md#L59)）
   → 动画/渐变背景会让这个值钉在测量瞬间，不会跟随。
4. **不要复用 `data-animating`**：那是侧栏/右栏开合专用，轨道与手柄共用 `--ds-transition-duration-slow`
   （[`layout README:96`](DSH文档/dsh-client-ui-layout__README.zh.md#L96)）。
5. **模态遮罩不模糊背景**（`--dsw-mask-blur: none`，[`web-styling:28`](DSH文档/web-styling.zh.md#L28)）：
   动效会透过遮罩可见 → 需要决定“弹窗打开时降速/暂停”。
6. **corner-shape 通配所有元素及 `::before` / `::after`**（[`web-styling:25`](DSH文档/web-styling.zh.md#L25)）：
   伪元素背景层要正圆必须配 `corner-shape: round`。
7. **不要碰滚动**（§14）：背景动效不得由 scroll 驱动，也不得给滚动容器加 animation。
8. **必须处理 reduced motion**：官方每个 keyframes 都配 `@media (prefers-reduced-motion: reduce)`，
   做法是“静止”而不是“隐藏”；减少动态效果是硬要求（[`web-styling:24`](DSH文档/web-styling.zh.md#L24)）。

### 16.3 官方没有的（不用再找）

- **没有背景/画布插槽**：slot 只有 `sidebar`、`main`、`rightbar`、`shell.bottom`、`shell.overlay`、`shell.leading`；
  没有 `background`，也没有 canvas/WebGL 钩子。
- **没有背景图/壁纸 token**（只有 `bg-mask-photo` 这类遮罩色）。
- **没有 reduced-motion 的 JS API**，只有 CSS 媒体查询；**没有“动效强度”设置项**（设置「通用」只有外观/字号/字体），
  要做开关得自己注册。
- **没有独立文档站**：文档就是各客户端包 README；`web-styling.zh.md` / `ui-radius.zh.md` 不在 npm 包里，
  本地副本来自 Desktop asar，可能滞后。

### 17.3a 环带：动态遮罩 + 4D 噪波色场（P1 v7，band-only）

- **遮罩（固定线宽、几何静止）**：基线宽固定 **8.54px**（12.2px 的 0.7×）；`wid=8.54`、`rad=R`，
  径向噪声与线宽噪声都已删除——**环完全不移动，只有颜色在动**。
  第三维一律用 `sin/cos(a)` 而不是 `a·k`，否则 2π 接缝会出现在环的右侧（已踩）。
- **调色板（遍历 `空洞.png` 取色，整体压深一档，不含暖白）**：天蓝 `#3f96dc`、蓝 `#4d6cd8`、
  蓝紫 `#6250ca`、紫 `#7845d2` / `#9645dc`、品红 `#b24cc4`、淡紫 `#b068c8`、淡蓝 `#6d8cd8`；
  Oklab 插值成 512 级 LUT，并把 LUT 的 **Oklab 色度 a/b 统一 ×1.18，并把 L 提亮 ×1.10。
- **色场（4D Perlin，参考 Blender 4D 噪波）**：每个角步取
  `n = .78·noise4(cos(a+rot)·0.55, sin(a+rot)·0.55, a·.07, morph) + .22·noise4(…·1.10, a·.14, morph·1.6)`，
  `t = 0.5 + 0.62·n` 映射 LUT。`rot = P·2π` 是整体旋转趋势，`morph = P·2π·1.8` 是第 4 维随时间演化，
  于是旋转中混入乱流，不再是从头到尾的规则转动。
  **色块尺寸约束**：沿环的单块色斑弧长 > `D/6`（D=760 时约 127px ≈ 19°），所以角频率压到 0.07 量级。
- **暖白**：不单独成层、也不常驻，出现时是**大块**而不是碎斑。用同一色场里的低频稀有子噪波
  `rare = .5 + .5·noise4(cos(a+rot)·0.6, sin(a+rot)·0.6, a·.06, morph·.7)`；
  `rare > 0.80` 时 smoothstep 混向 `#fff4e2`，再乘一个慢速 gate
  `g = smoothstep(0.55, 0.75, .5+.5·sin(morph·0.6+1.2))` —— 白只在部分时段开、大块出现（>30°）。
  白量数组再跑 **两轮 ±20 点环形平滑**（41 点，CPU 减半），让白与其他颜色之间的过渡和色场一样柔。
- **流动**：演示 GIF 12s/圈；**实机 60s 内转 6 圈（10s/圈）**，
  颜色/线宽的 4D 相位混两个分量：`wT = 1.6·sin(P·2π·5) + 1.0·cos(P·2π·4)`；
  分量周期 12s 与 15s，**组合周期 60s**；
  gate 25 周期/圈（2.4s 一次），菲涅尔呼吸 5 周期；
  暖白的稀有子噪波直接用同一个 `wT`（不再乘 0.7），**白的移动速度与颜色一致**。
  整数周期 → P=0/1 完全一致，仍无缝。
- **蓝紫时域占比**：调色板里蓝→蓝紫→紫区间扩到 0.10–0.56，t 采样偏到 `0.45 + 0.60·n`，
  时间上更多落在蓝紫色；这只是统计偏置，**任一时刻各颜色在屏幕上的占比不设范围**。
- **辉光**：`band` 用 `blur(96/52/24/9px)` 以 `lighter` 叠四遍（alpha 0.20/0.26/0.24/0.10）再叠原图。
- 每帧成本 = 1200 个角步 ×（1 次描边 + 3 次 noise4）＋ 5 次 drawImage。

### 17.3b 菲涅尔层（P1 v22，菲涅尔盖到光带中线）

- **球体**：CSS `.dome`，268px 圆（半径 134 = 环带半径），**不透明纯色 `#0d0d13`**，
  `clip-path: circle(50%)`。
  **不能再做半透明**：页面网点透过半透明 dome + screen 混合会产生同心摩尔纹，
  看起来像“一圈圈色阶”（2026-11-01 实测，不透明 dome 后立刻消失）。
  如果将来要保留一点透底，必须同时给 dome 加 `backdrop-filter: blur()` 先模糊网点。
- **最外侧硬边阴影**：画在光带 canvas 内（`?voidhide=shadow` 可关）：
  **纯色圆环** `R → R+34`，`rgba(0,0,0,.50)`（90% 透明），内外都是硬边，再叠到页面上压暗；
  不再用 DOM 层（会被列面板盖住）。
  **canvas 径向渐变坑（务必记录）**：`createRadialGradient` 超出终点半径的区域
  会**用最后一档颜色填满整个填充矩形**，所以直接 `fillRect` 会得到一个方块。
  必须先 `beginPath(); arc(C,C,外半径); clip()` 再 `fillRect`（或把填充限制在圆内）。
- **菲涅尔（球面投影，蓝紫主导）**：`.zzz-void-fresnel` 是 **canvas**，一次生成位图：
  - **盒 268px（半径 134 = 光带中线，按最终尺寸构建，无 transform 缩放）**；
  - **球面投影**：位图默认 `128×128`（可用 `?voidfres=` 覆盖），逐像素 `nx,ny ∈ [-1,1]`、
    `z=sqrt(1-r²)`，法线 `(nx,ny,z)` 在球面上采样 4D 噪波得到蓝紫/品红/青；
  - **alpha**：走**球面投影** `(1-z)^1.6`（z 为球面法线分量）；同时中心
    `0.1R` 以内**完全透明**，再用 `0.03R` 宽的 `smoothstep(0.10R → 0.13R)` 过渡回球面衰减，逐像素抖动后量化；
  - 没有 CSS mask、没有噪点覆盖层；`screen`、尺寸固定。
  - **径向流动**：**逐帧连续生成**（128² 实测约 1.8ms/帧），噪波 z 坐标按时间连续平移
    （`FRES_SPEED = 0.30 / 275` z 单位/ms），颜色由圆心持续向外缘流动，没有循环接缝；
    alpha 只算一次并复用，避免抖动闪烁。
- **层级**：环带 canvas `z-index:2`，dome/fresnel 在下——光带永远盖在菲涅尔上方。
- **光带**：短柱画成清晰环带；**近带辉光做浓、且高纯度**（不再做交界颜色混合）：
  - 内侧 `blur(34px)`，mask `R-110(0) → R-60(.70) → R-10(1)`，alpha 1.00；
  - 外侧 `blur(18px)`，mask `R-10(0) → R+15(1) → R+90(.85)`，alpha .95；
  - 紧贴层 `blur(8px)`，mask `R-45(0) → R-10(.90) → R+20(.90)`，alpha .78；
  - 三层辉光带 `saturate(1.75)`，保持纯度；
  - **本体用 `source-over` 最后叠**：辉光只在带外发光，不再以 `lighter` 加到光带上，
    避免光带被“加亮发白”。
- **颜色渗入（gTint）已去掉**：当前菲涅尔是纯 CSS 蓝紫径向渐变，沿环颜色变化由
  光带本体 + 辉光提供；对比版本里曾用 gTint 把光带颜色向内侧渗。
- **羽化仍回退**：逐短柱 `linearGradient` 会产生 alpha 叠加条纹；整带模糊副本做遮罩也不理想。
- **合成**：环带 canvas 920×920（给外辉光留边），**不带 `mix-blend-mode`（normal）**，
  叠在 dome / fresnel 之上——光带本体 alpha=1，是真正不透明的，菲涅尔不会透出来。
  画布内部的辉光仍以 `lighter` 叠加，只在带外表现为半透明光晕。
- 画布、dome、fresnel 同心（R=216，dome/fresnel 432px），后续油膜、二底都按这个几何叠。
- **性能**：DPR 上限 1.5；画布 1160（DPR1.5 时 4 张画布约 48MB）；
  面板不可见（IntersectionObserver）或 `document.hidden` 时跳过 render。

### 17.4 动效参数

| 动作 | 手法 | 时长 / 曲线 |
|---|---|---|
| 环带起伏 | 固定线宽 8.54px；径向 ±4.2px 噪声 | 线宽不再动态 |
| 颜色流动 | 4D 噪波：旋转 `P·2π·6` + 双分量 `wT`（5+4 周期，组合 60s） | 颜色只在 60s 重复 |
| 蓝紫占比 | 调色板蓝紫区间扩到 0.10–0.56，t 采样偏 `0.45 + 0.60·n` | 统计偏置，不限制单帧屏幕占比 |
| 辉光呼吸 | 三层辉光 alpha `0.20↔0.30` / `0.26↔0.36`（canvas 内） | 6.5s `--ds-ease-in-out` |
| 暖白 | 低频稀有子噪波 `rare>0.80` + 慢速 gate，大块出现 | 部分时段开合 |

全部 ≥6s、无频闪；缓动优先 `--ds-ease-in-out`（§16.1），旋转类用 linear。

### 17.5 跟随（迟滞 / 拖拽）

- **已实机实现（完全跟随 + 滞后）**：`window pointermove` 监听；目标 = 指针相对中栏中心的**实际像素位移**。
- **定位上下文**：`[class*="_centerCol"]` 必须 `position:relative` + `isolation:isolate`，
  `.zzz-void` 才能以中栏为 `inset:0` 基准并被 `overflow:hidden` 裁在中栏内；
  否则图层会按视口定位，既和鼠标错位、又会盖住侧栏（已踩）。
- 目标钳制在 `±列宽/2`、`±列高/2`；指针到边缘时圆心可以贴边，超出部分由中栏裁掉。
- 一阶平滑：`pos += (target - pos) * (1 - exp(-dt/tau))`，**tau = 180ms**，无过冲。
- 写入 `stage` 的 transform：`translate(-50%,-50%) translate(ox,oy)`（已无 scale）；圆、菲涅尔、canvas 一起移动。

**按下放大（2026-11-02）**

- `window pointerdown`（左键 0 / 右键 2）→ 目标缩放 **1.2**；按住保持；`pointerup` 且 `buttons===0`、`pointercancel`、窗口 `blur` → 回到 1.0。
- 一阶平滑：`zoom += (target - zoom) * (1 - exp(-dt/110))`，约 **110ms** 缓动。
- 缩放过渡期间**不冻结任何动画**：辉光与菲涅尔每帧照常重建，只把三层辉光画布改为**半分辨率**（blur 成本 ÷4，视觉无差），过渡时按 60fps 出帧。
- **光带线宽固定 8.54px**：只把半径放大到 `R*z`，线宽不参与缩放；tick 角宽按 `(TAU/N)*(R*z)*2` 重算。
- 菲涅尔 / dome 用元素 `transform: … scale(z)`；辉光 mask 位图以画布中心按 z 放大绘制。
- 画布从 570 扩到 **680**（半径 340），保证 1.2 倍时外辉光（`(R+149)*1.2≈339.6`）仍在 340 半径内。
- `prefers-reduced-motion` 时 **完全不跟随**（不注册监听）。
- 速度拉伸（scaleX/Y）与 0.22D 边界钳制尚未实现，可后续补。


- **文字可读性（2026-11-01）**：空洞是会话区背景，文字需要压住它——
  `[data-slot="main.conversation"]` 统一加 `text-shadow` 三层（0 0 2px / 0 1px 3px / 0 0 12px 黑），
  `pre, code` 排除。不要给正文加不透明底板（会破坏背景效果）。

### 17.6 性能与既有约束

- 只动 `transform/opacity`；`filter: blur` 只放在静态层，不随帧变。
- 玻璃面（composer / 玻璃卡）有 `backdrop-filter`，空洞从下面经过会触发重采样（§16.2-2）：P4 实测，
  必要时在空洞进入输入区时降 D 或暂停噪波。
- 不碰滚动（§14）、不碰 `data-animating`（§16.2-4）、不改任何 token。
- reduced motion：`@media (prefers-reduced-motion: reduce)` 关掉 17.4 全部动画；17.5 跟随保留但 `tau` 降到 60ms
  （无拖尾），外观不变（§16.2-8）。

**当前实际开销（2026-11-01）**

| 项 | 成本 | 说明 |
|---|---|---|
| 渲染上限 | 24fps | `t - last < 1000/24` 才渲染 |
| 菲涅尔 | 128² 逐帧生成 ≈1.8ms | 24fps 下约 4–5% 单核；`putImageData` 16k px |
| 光带 canvas | 680² × DPR(≤1.5) | 1200 根短柱 + 3 层 blur(10.5/5.5/2.5，半分辨率画布) 辉光 |
| 辉光 mask | 预计算位图（半分辨率） | 每帧只 `destination-in` 一次 |
| 跟随 | pointermove + 30fps 平滑 | 可忽略 |
| 空闲 | 页面隐藏 / 不可见时暂停 | IntersectionObserver + `document.hidden` |

**低配模式**：`?voidlow`、设置页「性能模式」，或 `hardwareConcurrency <= 4` / `deviceMemory <= 4` 自动开启：

- DPR 上限 1.5 → **1.0**；
- 菲涅尔纹理 128 → **96**；
- 菲涅尔生成改为**隔帧**；
- 帧率 24 → **20**（缩放过渡时 60 → 40）；
- **关掉紧贴辉光** `gTight`（三层里最贵、视觉最弱的一层）；
- DPR / 纹理属于建层参数，刷新后完全生效；其余即时生效。

**单一数值来源（2026-11-03）**：所有可调数值集中在 `client.js` 的 `VOID` 表
（`SIZE / RADIUS / BAND_W / SHADOW_W / ZOOM / FPS* / DPR* / FRES_* / GLOW_* / TICKS / WHITE_SMOOTH`），
调参只改这一处。`node tools/check-theme.mjs` 会校验：带宽/阴影比例 = 0.618、缩放后外辉光不超出画布、
低配参数单调、设置页 `settings.section` 注册存在、无 `scale(.62)` / `repeating-radial-gradient` 等不变量。

结论：主流集显/4 核机器可常驻；更老的机器建议开 `?voidlow`，或把渲染上限降到 20fps。

### 17.7 设置页（官方 `settings.section`）

按官方 Slot 注册，不写自定义入口：

```js
ctx.slots.inject('settings.section', () =>
  ctx.slots.register(
    { name: 'settings.section', id: 'zzz-theme', order: 70, label: 'ZZZ 主题' },
    ZzzSettings,
  ),
)
```

- 页面内目前两个开关：**空洞开关**、**性能模式**；
- 页头：24px 粗体 **「ZZZ 主题」** + 品牌黄 `ZENLESS ZONE ZERO` 小标，再进入「空洞」分组；
- 偏好存 `localStorage['dsh-theme-zzz:prefs']`（`{ void, low }`）；
- `voidPrefListeners` 让空洞 effect 订阅变化：
  - 空洞关闭：`layer.style.display='none'` 且 `visible=false`，渲染暂停；
  - 性能模式：菲涅尔更新立即变为隔帧；DPR / 纹理尺寸在刷新后完全生效。
- 控件自绘（`role="switch"` + `aria-checked`），只用 `--dsw-alias-*` token。

### 17.9 风险

1. `_centerCol` 是哈希类名（主题已有同类先例）；升级若改后缀需同步，查找时优先从 `[data-slot="main.conversation"]` 向上找。
2. 负 `z-index` 是否落在中栏背景之上，必须 P2 实测；不成立就用备选 B。
3. 深色页面上正片叠底偏弱，阴影可能几乎看不见 → 只调 alpha，不改结构。
4. 玻璃面 `backdrop-filter` 重采样可能掉帧 → P4 量。
5. 800px 圆盘的 `blur(34px)` 在低端 GPU 上有成本；不足时远辉光改预渲染 PNG 再旋转。
6. ⚠️ CSS `radial-gradient` 遮罩（mask）的**最后一站必须回到透明**：本次 P1 踩过——遮罩以
   `rgba(0,0,0,.35) 100%` 结尾时，最后一站的颜色会向外无限延伸，辉光方块铺满整屏（表现为四块方形色斑）。
   所有 mask / 半透明渐变收尾一律写 `transparent 100%`。
7. **canvas 性能**：每帧 1200 个角步 ×（1 次描边 + 3 次 4D 噪波）+ 5 次模糊 drawImage。
   桌面 GPU 应可接受，但必须在 P4 实测；不足时降 N 到 600、色场按 2 帧缓存或半分辨率绘制。
